- Model selector and Business/Personal toggle stay at the TOP of the chat UI — explicit user request.
- Do not reproduce a real company's site, copy, or assets; take design language only and build something original.
- No fake logos, invented customers, or made-up stats in any marketing copy.
- Repo is public: zero committed secrets, across the whole history. `errand-handoff.md` is gitignored.
- Speed is the priority — prefer acting over asking; parallelise independent work across subagents with strict non-overlapping file ownership.
- A subagent reporting success is not evidence; check the filesystem and the live URL. Two subagents once reported success having written nothing.
- A green deploy is not evidence the new code is serving; poll the live endpoint. A "deployed" backend once briefly served stale routes.
- `export UV_CACHE_DIR=/Users/macbook/prava/errand/backend/.uvcache` before every `uv` command — default cache is root-owned.
- Never name a zsh loop variable `path`; it destroys `PATH` for the rest of the shell.
- `gpt-5.6` needs `reasoning_effort="none"` for function tools on `/v1/chat/completions`, else HTTP 400.
- `az containerapp update --set-env-vars` preserves the other env vars; `--replace-env-vars` does not. Verify the var landed on the ACTIVE revision, not just the app.
- Auth register returns the JWT as `token`, not `access_token`.
- `email-validator` rejects reserved TLDs (`.invalid`, `.test`); use `example.com` for throwaway test accounts.
- Bound passwords in BYTES, not characters — bcrypt raises above 72 bytes and a multi-byte password inside a character limit still raises.

- Prava sandbox test card: 4622 9431 2313 7789, CVV 757, exp 12/27; test OTP 456789 (sandbox hosts only).
- A first chat turn claims its id via `window.history.pushState` (NOT router.push) to keep the SSE stream alive, so the App Router's rendered route stays `/c` while the URL reads `/c/<id>`. Consequence: `router.push("/c")` for "New chat" is a no-op (route already `/c`), so ChatView is reused and never resets — the fix is to watch `usePathname()` and blank the view when the route says new-chat while it still holds an id.
- Voice sessions bound NO conversation id (relay takes only model/profile/ticket), so starting voice on a fresh chat left activeId null and a typed turn afterward minted a SECOND chat. Fix: claim the id up front (shared `ensureConversation()`) on BOTH first-type and voice-start so the spoken run and typed turn share one id/URL.
- The cart ignored the user: `build_cart` never read `intent`, only `context.budget_cents`, and `_select_items` fills to budget — so "under $10"/"cheaper" produced the same cart every time. Fix: optional `max_cents` on the run_errand tool → min(policy, cap) applied to a COPY of the shop context (policy stays the ceiling; empty capped cart aborts, never a $0 session).
- Prava passkey iframe was fixed h-320px and clipped the card→OTP→passkey flow ("not opening in full"); use a tall viewport-relative height (clamp(560,78vh,760)).
- Cloudflare Browser Rendering exposes full CDP (screencast IS a CDP command) but for a verifiable live view use periodic `page.screenshot(jpeg,q45)` pushed over SSE, throttled ≤2/s, reducer keeps LATEST frame only (bounded). Raw CDP screencast is unverifiable against the CF endpoint without a live account.
- Agentic browser shopping: `app/orchestrator/agentic_shop.py` is a driver-agnostic observe/add/remove/done loop (no Playwright, no OpenAI imports) so it unit-tests with a fake surface; the Playwright `_PlaywrightShopSurface` drives the demo DOM (`data-add`/`data-remove`/`#cart-lines li[data-line][data-qty]`). Loop enforces `_is_disallowed` + budget; LLM only chooses. Verified LIVE against the real store (banned item refused, 5 frames, DOM total).
- The pathname-watch new-chat fix was WRONG: `router.push("/c")` after a `pushState` to `/c/<id>` is DEDUPED, so usePathname never flips back and the reset effect never fired — it shipped still-broken. Correct fix: a `newChatNonce` counter in the shell that `openNewChat` bumps; ChatView resets on the nonce change (plain React state through context, router-independent). Lesson: never gate a UI reset on Next router/pathname behaviour you have not confirmed actually changes; an explicit signal beats inferring from the router.
- The chat model only has `run_errand` + `web_search` tools — there is NO general "open/browse a URL" tool, so "open SHEIN" is correctly refused. The live browser only runs INSIDE run_errand against the demo store DOM. A general browse tool, or real-merchant shop+pay, is separate unbuilt work (real-merchant = money, human-gated).
- Prava wallet is SINGLE-VARIANT per checkout (quote/checkout take one variant_id / one session) — there is NO multi-product basket, so "add 5 things, pay once" is not a supported shape; multiple items = multiple orders. Guest checkout only (Amazon/SHEIN-style authenticated checkouts unsupported), US-only Visa (not Chase/Ramp). So the real-merchant agentic loop is SELECT-a-variant, not add/remove; `PravaShopBroker.agentic_build_cart` lets the LLM pick from the policy+budget-filtered candidates and falls back to top-ranked on a bad pick.
- Wallet/real-merchant path drives no browser WE own, so there is no screenshot: `on_frame(step,detail,None)` → emit as an AUDIT line, never a `browser.frame` (a frame with no image blanks the live view). shop.* audit steps render as StatusLines.
- CLOSURE-NAME TRAP: a name used only inside a nested async fn (`_now()` in chat.py's on_frame) is NOT caught by a module import check — the module imported fine but would have crashed at call time. `_now` lives in run_errand.py, not chat.py; used `datetime.now(timezone.utc).isoformat()` inline. Grep for the name's definition in-file, don't trust import success.
- Cloudflare Browser Run has native Live View + Human-in-the-Loop: `Cloudflare.getLiveView({mode:"tab"})` → interactive `live.browser.run` URL (verified `frame-ancestors *`, so iframe-embeddable); `Cloudflare.handoff`/`handoffComplete` for structured takeover. Python Playwright sends these via `ctx.new_cdp_session(page).send(...)` (no `.once()` — use `.on()`+future). keep_alive max 600000ms (10 min) is an INACTIVITY cap → ping during a human wait or the session idles out mid-payment.
- Live handoff = agent shops, HUMAN pays in the live browser (agent enters no card). Refuse local targets (no Live View for local Chromium). Gated by `use_live_handoff` + Cloudflare creds (`settings.live_handoff_ready`); the shop_live tool is only offered to the model when ready, on BOTH chat and voice.
- Feature parity across chat AND voice is a hard requirement (user): the agentic shop loop, live frames, and live handoff must work on both. Achieved by (a) extracting `make_shop_decide` to `app/orchestrator/shop_decide.py` so both callers share it, and (b) the voice hook folding unknown frames (`browser.frame`, `browser.liveview`) through the SAME `applyFrame` reducer. The voice human-done signal reuses the existing `{type:"approve"}` control message — but `browser.liveview` must ALSO set `approvalRunIdRef` (no `approval.request` fires on that path) or the Done button has no run_id.
- Voice think model is Deepgram-managed Anthropic (no gpt-5.6), but the shop_decide call is a SEPARATE OpenAI-compatible call, so it uses `self._model_id` (gpt-5.6-*) with reasoning_effort="none" — same as chat.
